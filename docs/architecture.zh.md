# 架构说明

Solidway 的内部构造。行为规格见 [`openspec/specs/`](../openspec/specs/)；设计动机见 [`docs/adr/`](adr/)。

## 进程布局

一个进程里有两个面：

```text
                    ┌──────────────────────────────┐
  LLM 客户端 ──────►│ 数据面（solidway-core）       │─────► 上游端点
  （脚本、SDK）      │ 转发 · 选号 · 健康            │
                    │ 用量统计                     │
                    └──────────────┬───────────────┘
                                   │ 事件
                    ┌──────────────▼───────────────┐
  控制台 ──────────►│ 管理面                       │
  （浏览器）         │ API · 认证 · SQLite · TLS    │
                    └──────────────────────────────┘
```

数据面的**全部实时状态都在内存**：凭据健康、冷却截止时间、选号指标、会话粘性。它对外发布事件，管理面据此落用量、故障记录与告警。

## Crate 划分

| Crate | 职责 | 依赖 |
|---|---|---|
| `solidway-core` | 数据面：转发、选号打分、健康与探测、用量统计、会话粘性。不碰数据库，不提供管理 HTTP 面。 | — |
| `solidway-api` | 管理面：SQLite schema 与查询、HTTP API、会话认证、Provider 目录、TLS/ACME、告警、控制台托管。 | core |
| `solidway` | 二进制：解析 `data_root` 与生命周期参数，装配两个面，处理信号。 | api |
| `solidway-egress` | 需要特殊处理的出站请求成形。 | transcode |
| `solidway-transcode` | 协议转换原语。**在树内，但尚未接入转发路径**。 | — |

前端与外壳：

| 路径 | 职责 |
|---|---|
| `web/` | React 控制台（Vite、shadcn 风格组件、i18next）。release 构建时嵌入二进制。 |
| `app/` | Tauri 2 桌面外壳，独立 cargo workspace，不在根 workspace 内。 |

## 请求生命周期

```text
入站匹配 ──► 按 API Key 解析路由 ──► 选号
      │                                │
      │                     score = f(权重, 延迟, 错误率, 冷却)
      │                                │
      └────────────► 转发上游 ◄─────────┘
                        │
           首个字节？ ──┴──► 提交：此后不再换号
                        │
                流式帧透传
                        │
             记录用量 + 释放槽位
```

### 允许改动的位置

转发是逐字节保真的，例外是一份五项白名单：入站鉴权头替换为凭据自己的头；目标地址按凭据的 base URL
与路径模板重建；query 中携带凭据的参数（`key`、`api_key`）被移除；模型别名生效时改写请求体顶层
`model`；**成功响应**的顶层 `model` 回写为客户端模型名。没有别名映射的模型完全不碰。

Header 按值转发，**顺序与大小写不保留**（HTTP 层用 map 存储），因此依赖原始 Header 字节做签名的上游
不在支持范围内。

换号只发生在**首个字节到达客户端之前**；之后响应已提交，上游失败会作为错误暴露，而不是拼接两段响应。

## 数据模型

SQLite，两个库：

- `solidway.db` —— 用户与会话、路由、Provider 凭据、API Key、设置、凭据健康、故障记录、运行时快照。
- `usage_detail.db` —— 逐条请求明细，保留条数与采样率在设置里配置。

Provider 凭据用 AES-256-GCM 加密，数据密钥由 `master.key` 派生。控制台会话是服务端会话 + Cookie。

## 状态与重启

- 健康、冷却与会话粘性在内存中，重启时从关闭阶段写入的运行时快照恢复。
- 关闭阶段在固定预算内落盘用量与快照，然后退出。
- 选号指标由最近的尝试分桶聚合而来，重启不会重置观测到的质量数据。

## 控制台与桌面外壳

- 控制台是 SPA，只访问 `/api/*`；数据面（`/v1/*`）与它无关。
- 桌面外壳把网关作为子进程托管，读取其机器可读的 stdout 事件（`solidway: …`），并在 webview 中打开控制台。
- `--mode desktop` 下，托管方关闭 stdin 时进程立即退出，因此外壳崩溃或被强杀不会留下孤儿进程。
