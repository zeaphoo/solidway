# ADR 0016 — 桌面免登录：壳持有进程级令牌，自动签发 admin 会话

## 状态

已接受（2026-10-23，随 `desktop-auto-login` 落地）

## 背景

桌面模式此前只依赖 webview 里的会话 cookie（默认 24h）。口设令置完成后服务不再签发任何令牌，于是以下路径都会落到 `/login`：会话过期、点击「退出登录」、改端口/启 HTTPS（origin 变化）、webview 数据被清、忘记口令。桌面用户多数只在小程序/控制台里用过一次口令，锁死后 UI 内无自救路径（只有 CLI `--reset-password`）。

桌面端的真实信任边界是 **OS 用户**：能读 `<data_root>` 的人已经拿到 `master.key` 与数据库，外加一道口令对本地攻击者没有增量保护。因此「本机控制台免登录」是合理的产品语义，但**不能**扩散到网络。

## 决策

1. **令牌而非免鉴权**：服务每次以 desktop 模式启动时生成 32 字节随机令牌（内存只存 SHA-256），bind 后经 stdout `solidway: desktop-login url=…` 交付给壳；壳把它当作导航用的 fragment。
2. **令牌是能力**：进程内可重复使用（支持会话过期自动续），进程重启轮换；不落库、不写日志、不经任何已认证接口返回。信任模型是「持有令牌者 = 本地壳」，不做额外的 loopback 对端校验（明文与 TLS 两套 serving 路径未统一注入 `ConnectInfo`，后续 hardening 另立）。
   登录地址 MUST 走本机回环（通配绑定归一化为 `127.0.0.1`/`[::1]`），**不使用**公网 / TLS 域名：desktop 模式可能同时对外提供服务，管理员令牌不得经过对外入口。外部客户端仍使用普通登录，会话按客户端隔离。
3. **固定 admin 身份**：桌面 = 机器主人形态。多用户切换仍走「退出登录 + 口令」。
4. **保留「退出登录」**：控制台用于创建/切换用户；显式退出会清掉本地令牌（`sessionStorage`），不会被静默拉回 admin。回到 admin 的显式入口是托盘「以管理员自动登录」。
5. ~~**首启引导优先**：admin 处于锁定态（`password_hash = '!'`）时自动登录一律拒绝，必须先在引导页设置口令——否则桌面免登录会绕过首次设口令。~~ **已由 ADR 0017 修订**：桌面模式不再引导设口令，锁定态 admin 可用令牌登录，口令改为控制台内可选设置。
6. **用事件修掉引导死链**：引导令牌被消费后服务输出 `bootstrap-consumed`，壳清空引导地址，后续托盘打开改走桌面登录。

## 被否方案

- **desktop 模式对 loopback 请求免鉴权**：`bind_addrs` 可以配成 `0.0.0.0`，LAN 客户端也能被当成「本地」；且与多用户/远程使用场景冲突。
- **隐藏「退出登录」**：控制台要用于创建与切换用户，隐藏会让多用户场景失去入口。
- **延长会话 TTL / remember-me**：治标，退出与端口变化仍会锁死。
- **一次性令牌**：会话过期后无法自愈，需要另做刷新协议；进程级复用 + 重启轮换已能覆盖。
- **壳直接写会话 cookie**：Tauri 无稳定的跨平台 API，且绕过服务端会话表。
- **自动登录「记住上次用户」**：需要壳持久化用户标识与多套令牌，当前桌面形态是单主人，YAGNI。

## 后果

### 正面

- 桌面启动、端口变化、webview 数据清空后都能免密进入；
- 退出登录仍可用，切用户后可用托盘一键回到 admin；
- 口令、引导、standalone/远程访问语义完全不变；
- 令牌不新增监听端口、不新增持久化文件、不触碰 JS 能力面。

### 负面 / 风险

- 令牌在 URL fragment 中出现一次（读取后立即 `replaceState`），依赖控制台「不把 fragment 发给第三方」；同源页面本来就有会话，风险可接受；
- 未做 loopback 对端校验，信任完全落在「令牌只经壳 stdout 交付」上；
- 固定 admin：多用户桌面切换仍需口令；会话过期后非 admin 用户不会被自动续期（本地令牌只属于 admin 入口）。
