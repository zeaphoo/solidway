# ADR 0018 — Dock 重开同路径；「打开控制台」可用性与 Dock 图标随窗口存在性

## 状态

已接受（2026-10-27，随 `tray-menu-dock-reopen` 落地；同日范围扩展增补决策 3，Charles 裁决方案 A）

## 背景

「关闭窗口时最小化到托盘」下关窗后应用常驻托盘，但 macOS 点 Dock 图标无法重开控制台（`RunEvent::Reopen` 落入 `_ => {}` 被吞）。同时窗口不存在时，托盘「打开控制台」与「以管理员自动登录」实际走**同一路径**（重建窗口 + 桌面令牌登录；desktop 模式恒定无引导事件，ADR 0017）——两个可点项行为完全重复，且「打开控制台」这个命名在该状态下失真：它做的不是「打开」，而是「重建窗口并建立 admin 会话」。同理，窗口不存在时 Dock 上常驻一个「点开就是重建会话」的图标，与上述语义失真是同一问题的两个表现。

## 决策

1. **Dock 重开 =「打开控制台」同路径**：`RunEvent::Reopen` 一律复用 `supervisor.open_console`（窗口在 → show + focus，不在 → 重建），不新增第二条打开路径；处理臂以 `#[cfg(target_os = "macos")]` 门控——Tauri 的该变体仅 macOS 存在，其他平台在编译期即无此分支。
2. **「打开控制台」可用性跟随控制台窗口存在性**：窗口不存在时置灰（保留菜单项、不可点），只留「以管理员自动登录」可用；窗口创建成功后恢复、销毁后重新置灰。
3. **Dock 图标与控制台主窗口同生命周期（方案 A）**：窗口存在时 activation policy `regular`（Dock 图标可见），不存在时（关进托盘 / `--hidden` 启动未开窗）`accessory`（图标隐藏，应用与托盘继续运行）；切换与决策 2 共用同一同步时机（创建 / 销毁）。**恒隐藏（`LSUIElement`）被否**：窗口存在时 Dock 图标必须可见。

三条决策同源：**「窗口存在性」是唯一状态源**（判据只算控制台主窗口，splash / notice 不计入），菜单置灰与 Dock 图标显隐是同一状态的两个表现。置灰的语义理由：窗口不存在时「打开控制台」与「以管理员自动登录」完全同义，保留两个可点项是冗余且命名失真；置灰（而非删除）保留菜单结构与位置记忆，把「重建 + 建会话」的语义显式归给名字正确的那一项。

## 被否方案

- **恒隐藏（`LSUIElement`）**：窗口存在时也没有 Dock 图标，「窗口存在时点 Dock 聚焦」与 macOS 惯例（应用随窗口显隐 Dock 图标）都不成立；Charles 裁决明确否决。
- **`set_dock_visibility(bool)`**：同一 runtime 消息通道，仅切 Dock 显隐、不改应用形态；裁决口径是 activation policy（`regular` / `accessory` 同时决定菜单栏与激活形态，与「关进托盘」的应用形态一致）。若实现期实测该 API 语义更贴合，可回报评审后替换，行为契约不变。
- **按偏好 / 配置决定 Dock 显隐**：引入第二个状态源，违背「文件内容 == 壳实际行为」的既有不变式；YAGNI。
- **「打开控制台」在窗口不存在时直接重建**：与「以管理员自动登录」继续并存两个行为相同、命名不同的入口，语义失真保留下来。
- **删除 / 隐藏该菜单项**：菜单结构随状态跳变，用户失去固定位置；置灰保留可见性与位置记忆。
- **Dock 重开单独实现一套重建逻辑**：与托盘路径重复（DRY），日后必然漂移。
- **`has_visible_windows` 为真时忽略 Reopen**：窗口最小化时点 Dock 需要还原，统一走 show + focus 更简单，也更符合 macOS 习惯。

## 后果

### 正面

- Dock 图标自解释：图标在 ⟺ 控制台窗口在；窗口存在时点 Dock 是纯聚焦，无副作用；
- 托盘菜单不再有两个同义入口，状态自解释（可用 ⟺ 控制台窗口存在）；
- 关进托盘后系统界面上不再残留「点开就是重建会话」的入口，语义与菜单置灰一致。

### 负面 / 风险

- 窗口不存在时找回控制台的入口收敛为托盘「以管理员自动登录」（Dock 图标隐藏，macOS 惯例如此）；`Reopen` 兜底仍覆盖 Finder / `open -a` 等系统路径；
- 隐藏启动（`--hidden`）后第一次进控制台同样走托盘入口——去重与方案 A 的直接推论，已接受；
- 服务未就绪时点击沿用现状提示，不因本决策改变（范围外，见 `docs/future-roadmap.md`）。
