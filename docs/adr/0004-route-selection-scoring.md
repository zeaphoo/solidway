# 路由选号：策略在路由级、指标在数据面内存

状态：accepted（2026-10-20，用户裁决）

## 背景

在引入策略之前，选号只有一种行为：同一路由内**轮询**。`provider_keys.weight` 字段存在但数据面明确忽略。结果有三件事做不到：

1. 无法表达成本偏好（同路由既有便宜 key 又有兜底 key，只能平均分摊）；
2. 无法表达性能偏好（某个 provider TTFB 明显更低，仍分走一半流量）；
3. 无法快速摘掉某个 provider（只能停用或删除，前者退出所有格式与模型）。

llmgateway 的选号是加权打分（price / uptime / throughput / latency + provider priority + 指数 uptime 惩罚 + 1% 探索）。本仓库需要对齐**机制**，但有三条本地约束：

- 定位是「企业自有账号池 + 不对外售卖 access」，**不做计费**，没有价格与吞吐数据源；
- 数据面 `solidway_core` 的硬边界是**纯内存**（不碰 DB），因此任何指标只能自己测量或由控制面推送；
- 客户端脚本零改动的承诺意味着**不能引入请求级参数**（llmgateway 的 `routing` 字段属于客户端可感知的协议扩展）。

## 决策

1. **策略作用域 = 路由**。每条路由一个策略，取 `round_robin`（默认）/ `uptime` / `latency` / `auto`；不做请求级 `routing` 参数。
2. **存储 = 枚举列 + 覆盖项 JSON**。`routes.selection_strategy` + `routes.selection_config`（只存用户显式改过的字段），解析时与内置默认值合并；新增参数不需要迁移。`provider_keys.priority`（`1..=1000`，缺省 1）是**档位**，schema 中不存在 `weight` 与 `sort_order`；`priority` 的 `CHECK` 为 `1..=1000`，`0` 不是合法档位，「暂时不参与选号」用 Provider 停用表达。
3. **指标 = 数据面内存 EWMA**。成功取首字节时延、标记类失败取失败率（α = 0.2）；无样本或距最后样本超过 30 分钟视为未知，用阈值兜底值。重启清零，不落库。
4. **打分公式对齐 llmgateway 的结构，但去掉 priority 项**：
   `score = (w_uptime/Σw)·uptimeRatio + (w_latency/Σw)·latencyRatio + uptimePenalty`；
   排序键是 `(priority 降序, 档内分数/轮询, 计数器)`；权重和 ≤ 0 回退轮询；同分按轮询计数器打散（公平 + 探索）。
5. **本轮权重只有 uptime 与 latency**：`w_price` / `w_throughput` 字段保留但必须为 0（管理面 422 拒绝非 0），避免"存了却被静默忽略"。

## 被否方案

- **请求级策略参数**（`routing: "price"`）：与「客户端零改动」冲突，且把运维意图交给调用方。
- **策略放在 provider 上**（每 provider 一个权重）：表达不了"这条路由整体怎么选"，且换策略要改 N 条记录。
- **指标从 DB 聚合**（llmgateway 的时间衰减窗口）：数据面读库破坏纯内存边界；由控制面推送指标则引入延迟与一致性负担。
- **沿用 `weight` 字段承载优先级**：语义相反（权重是"分摊比例"，优先级是"偏好与排除"），且 `0` 在两者含义不同；最终直接删除了 `weight` 与 `sort_order`，不留第二条顺序路径。
- **priority 做成 llmgateway 式的 0..1 软惩罚**：`(1 − priority)` 会在整数档位下碾压权重（1 vs 2 就相差 1 分），"先用 A 组再用 B 组"的意图无法表达；改为分档后，它既不干扰分数，也能表达硬偏好。
- **先做价格优先**：需要模型价格目录与上游 id 对齐，是独立工程；本轮先落地不依赖外部数据的两种策略。

## 后果

- 默认策略是轮询，**存量路由行为零变化**；指标冷启动时全部未知，等价于轮询。
- `weight` 与 `sort_order` 已从数据库、接口与界面删除；顺序与偏好只由 `priority`（档位）表达。
- 打分公式已按「归一化 ratio + 惩罚项」定型：后续加价格/吞吐只需新增一个 ratio 与权重，不需要改候选过滤与换号逻辑。
- 缓存型上游（prompt cache）与探索的交互暂未处理：`auto` 的探索请求会绕过打分，可能打掉缓存命中；若成为问题，可在 P2 用会话粘性抑制（现有粘性已置顶，故影响有限）。
- 指标随进程重启清零，长尾问题（如每日一次的抖动）不会被记住；这是换取"数据面零持久化"的代价。
