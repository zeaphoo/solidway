# Project Brief — solidway

## 项目定位

自托管的 LLM 接入网关：企业自购若干账号组成池子，交给自己的员工与脚本共用；网关按协议族提供保真转发通路，在转发之外完成账号健康判定、无感切换、用量归因与分账。

一句话定义（讨论稿 2026-10-07）：**gateway，不是中转站**——账号归客户自有，使用者是客户自己的员工与脚本，收入来自软件许可 + 支持服务，不对外售卖模型访问权限。

## 当前阶段

- 状态：管理面（DB + 管理 API + Web 控制台）与数据面（纯内存 `solidway_core` 转发引擎）均已落地，规格基线为 4 份 specs（`gateway-core` / `management-api` / `admin-console` / `desktop-app`），详见 `openspec/specs/`。
- 业务需求以 `10. Projects/SolidWay/solidway LLM 网关 Handoff（2026-10-07 讨论稿）`（Obsidian Vault）为讨论基线；「已确定」为讨论共识、「建议」非结论。

## 已确认方向与边界约束

- 客户端以脚本为主，核心承诺：账号不可用时脚本零改动（换号仅限首个字节之前）。
- 池化单位是「限额域（quota domain）」，key 只是域的凭据；消费侧按路由（route）寻址，一条路由由一组 provider 凭据共同提供服务。
- 上游政策处置（封禁等）：401 等凭据失效类错误按永久退役处理（隔离，需人工恢复）；403 等只表明账号异常、封杀未确定前按临时不可用换号（冷却）；确定封杀的处置不自动切换。
- 不跨协议翻译；请求体 / 响应体 / 流式事件保真转发。
- 明确不做：对外售卖 access、订阅账号拼车、内容审核 / 改写。

> 本文件只记定位与边界，不写业务行为；业务行为以 OpenSpec 为准。
