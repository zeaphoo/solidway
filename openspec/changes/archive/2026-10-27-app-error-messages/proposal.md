# app-error-messages

## Why

桌面壳的错误呈现目前只是「技术错误串 + 日志路径」，用户看完不知道该做什么：

- 找不到 `solidway` 时只写「未找到可执行文件 + 已尝试路径」——用户不知道这是**安装不完整**，也不知道该重新下载；
- 端口被占用时虽然拼了占用者，但没告诉用户「关掉那个程序再重试」；
- 崩溃/超时时只给日志路径，用户还得自己去翻文件。

## What Changes

错误页按**失败分类**给出「标题 + 建议 + 日志末尾」，纯文本、无按钮：

| 分类 | 标题 | 建议要点 |
|---|---|---|
| 找不到二进制 | 安装可能不完整 | 安装包下载不全 / 被隔离 → 重新下载安装 |
| 不可执行 | 服务程序无法运行 | 缺执行权限（解压方式）→ 重新安装 |
| 其他启动错误 | 服务启动失败 | 详情见下 |
| 端口被占用 | 端口被占用 | 关闭占用程序后重试；若是另一个 solidway 说明上次未正常退出（**不自动杀进程、不自动换端口**） |
| 端口无权限 | 没有权限使用该端口 | <1024 端口需特权 → 改用高位端口 |
| 异常退出 | 服务启动失败 | 附日志末尾 |
| 握手超时 | 服务没有按时就绪 | 附日志末尾 |

日志末尾：读 `<data_root>/solidway.log` 末 20 行，去 ANSI 颜色码，按字符截断到 2000 字符内嵌在错误页；日志不存在则省略。

不修改：`open_action` 的状态分流（不覆盖原因）、托盘行为、端口配置来源（仍只来自服务端 settings，壳不 override）。

## 验证要求

- `cargo test --manifest-path app/Cargo.toml`：新增 `bind_failure_classification` / `spawn_error_classification` / `failure_copy_is_user_facing` / `ansi_is_stripped`，共 21 条全绿。
- 手工：资源目录缺 `solidway` → 错误页标题「安装可能不完整」且建议含「重新下载」；占用 6565 → 标题「端口被占用」+ 占用者 pid/comm + 日志末尾。
